# Story 1.6 input telemetry producer v1

This is the current client producer and isolated browser validation contract for Story 1.6 T6. It implements the four canonical input/import events in `docs/front-end-spec.md` using `nomad.telemetry.v1`. The App's default producer binding is unavailable. A real host SDK, versioned legal consent UI, U-Link/U-App attribution, operator query, native device behavior, and production delivery remain separate work; this local evidence does not close T6 or the Story.

| Event | Actual producer boundary | Safe properties |
| --- | --- | --- |
| `home_input_submit` | Explicit send of a nonempty Home composer | None |
| `home_input_classified` | Current owner's successful parse response | `classification`, bounded link and unrecognized counts |
| `ingest_job_created` | Confirmed `created` mutation receipt after the persisted operation is accepted | `disposition: created`, initial `attempt: 1` |
| `ingest_presented` | HomeImportDock layout acknowledgement for a visible completed result | Actual attempt and positive `stored_count` |
| `import_record_opened` | Protected result read followed by visible Sheet content | No invented `partial` value when the result DTO lacks it |

Background terminal facts, SSE reconnection, recovery GET responses, and an opened loading Sheet do not create these events. A new explicit result open gets a fresh random event ID. The Dock completion and result heading are acknowledged only after they intersect the visual viewport and win the hit test against covering content. A pending Dock completion is checked every 250 ms until it becomes visible or is removed, so a long keyboard/overlay obstruction does not strand the FIFO window. Result view observation is bounded to two seconds or 180 frames and stops on close, hidden content, or stale request; losing telemetry never changes the displayed result.

Before an async action, `InputTelemetry.capture` freezes the installed analytics binding and the current auth epoch/activity. It rechecks these, the registration generation, and the producer's validity predicate before emission. The existing runtime separately requires the current policy version, granted consent, and a live context generation; revocation or owner changes abandon old work. There is no provider fallback, disk spool, raw event payload retention, or success claim for an unavailable binding. Queue/derivation limits remain 64; a full queue can lose telemetry while the import proceeds.

`ingest_job_created` and `ingest_presented` use `nomad-input-event-v1`: SHA-256 of the UTF-8 JSON array `[profile, event name, lowercase server UUIDv4 without ing_ prefix, attempt]`, taking the first 16 bytes and setting UUID version 8 and RFC variant bits. The exact vector `ing_00000000-0000-4000-8000-000000000001` / `ingest_presented` / attempt 2 gives `87ac5d88-c6d1-859c-89e6-b81c77b36056`. This preserves event identity for a repeated job/attempt presentation across restart or delivery retries while distinguishing event names and attempts. The profile accepts only syntactically valid server UUIDv4 jobs, initial creation attempt 1, and attempts 1–10000. It is an opaque observation reference, not an owner identifier, access token, erasure proof, or general UUIDv4. The runtime accepts UUIDv8 only for those two event names. RFC 9562 §5.8 and Appendix B.2 specify the custom UUIDv8 space and SHA-256 construction example; WebCrypto performs the digest in browsers.

The dictionary is the before-send field and value allowlist. Raw text, URL, source title, owner/session/auth identifiers, location and result content never enter the envelope. Host adapters must also disable automatic request/form/replay capture and must honor close/abort before any SDK call. The current browser fixture sends only sanitized envelopes to its owned loopback path, with all other external requests aborted and counted. It uses the actual App, controller, encrypted IndexedDB journal, and Chromium rendering; HTTP, identity, consent and telemetry sinks are explicit substitutes. No real authentication, SDK consent, provider query, U-Link/U-App delivery, or native device is verified by this probe.

Run `pnpm run ci:input-telemetry-browser` after installing locked Puppeteer Chrome. `INPUT_TELEMETRY_OUTPUT` chooses an empty output directory; the default is ignored `.telemetry-results/input-<uuid>`. The report includes source hashes, observed envelopes/counts, sink counters, explicit fixture flags and boundary checks. CI preserves the output as an artifact.
