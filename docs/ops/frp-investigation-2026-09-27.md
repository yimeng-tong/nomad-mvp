For Nomad, the home ISP's blocked inbound 80/443 does not prevent a dedicated `frpc` on VM104 from making an outbound TLS control connection to Alibaba Cloud. The current frps uses one shared token; [upstream FRP authentication documentation](https://gofrp.org/en/docs/features/common/authentication/) requires the same token on client and server. Copying that credential to Nomad would couple the old OpenList port and the new API. Prefer a separate frps instance with its own control listener, token and proxy port, kept server-side, plus an Alibaba Cloud public HTTPS virtual host and certificate for the Nomad hostname. This leaves OpenList's 25244, configuration and failure history untouched. The VM104 client should target a private reverse proxy to its loopback development API. The current app is bound to `127.0.0.1:43104`; its real login Origin/audience and native acceptance remain open. Verify exact DNS, cloud security group, TLS chain, owner/auth/CORS behavior, SSE, external network path and rollback before marking the public API available. This is a proposed route, not a deployed Nomad FRP tunnel.
