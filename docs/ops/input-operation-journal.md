# 已确认输入操作日志：存储核心

Story1.6 T6开发中。存储核心已接入Home控制器与外链inbox；真实Chromium两进程验证客户端恢复，鉴权/API/剪贴板/深链投递仍为明确替身。真实U-Link/U-App、原生设备和工程测量未关闭，整Story保持in-progress。

## 权威和数据边界

`operation-journal.ts`保存本机已确认动作的稳定操作编号；业务是否受理、当前job/attempt/结果仍由服务端命令回执和快照决定。调用方使用当前已核验owner及绑定epoch/activity的`valid()`栅栏。本地数据不会成为身份、权限或服务端成功的证明。

- `prepare`原子保存整批开始操作；可选多个输入指纹与批次同事务绑定。重复指纹只返回同owner的原始start记录，顺序/总数保持，后来的retry不混入批次。
- `prepareRetry`保留原entry身份，为当前明确重试保存新operation及原job/预期attempt/state_version；若尚有未知retry，返回同一个操作编号，先对账。即使原始start缓存先过期，也可消费仍保留的entry记录。
- `mark`只记录客户端最后获知的结果。accepted不能被迟到的拒绝覆盖；远端回执仍需重新核对。`noteDone`在实际完整完成展示后记录已展示attempt，不能在后台靠计时器假称结果已展示。
- `claimed`只提供本地已确认指纹的存在性，不把指纹/渠道/点击ID当账号。未确认composer不写入本日志。

## 存储和保留

IndexedDB三个object store：operations、claims、keys，每类最多2048条。事务请求strict durability，完成后才返回成功；不支持、配额不足、升级阻塞、连接失效或数据损坏均返回明确错误，没有进程Map/普通localStorage成功降级。

开始请求正文用AES-GCM256随机IV加密；AAD绑定版本、owner、operation和kind。每owner的不可导出CryptoKey也存于IndexedDB。这是私有输入的本机缓存保护，**不是Keychain/Keystore凭据存储，也不能抵御同源脚本被控制**；认证凭据继续使用1.0自己的安全传输/存储。实现依据[Web Cryptography序列化模型](https://www.w3.org/TR/webcrypto-2/)及[IndexedDB事务模型](https://www.w3.org/TR/IndexedDB/)。密码操作在事务外完成，IDB事务内部仅使用请求回调，不在事务中等待网络或密码操作。

私有正文24小时后逻辑失效，在下一次访问/维护时清除密文；已确认受理时立即清除正文。操作/指纹元数据保留7天，owner密钥按最后使用刷新7天；清理在存储活动中执行，离线关闭期间不声称已经物理擦除。重试仅含公开job/版本引用，按元数据期限保留，以免正文期限届满使未知重试失去原请求身份。清理只针对这份设备缓存，不操作业务数据库、媒体或备份。

## 当前接入规则

1. Home确认发送/重试时先调用日志prepare；事务完成后才派发原operation。持久化失败保留输入并停止派发，不生成替代ID。
2. App在同owner身份确认后恢复记录；重建批次与原entry，先GET原命令回执和job快照。恢复本身不POST；未知请求必须由用户明确继续，并读取原请求/operation。
3. 外链放入composer时保留当前输入指纹上下文；只有未被用户修改的已确认动作才绑定该指纹。确认后的热/冷重复事件消费已存在的记录，不重新创建动作；跨owner保持隔离。
4. 将已过期/损坏/不可用与网络未知区分；业务成功以服务器回执显示，不能因本机记录更新失败否认已知受理。完整FIFO展示后的标记及恢复行为需要同一验证矩阵。
5. 补浏览器重载/新进程中的实际控制器与受保护API替身闭环，再补真实双端运行、归因和工程测量。测试fixture只能显式注入，生产路径不能自动退回内存日志。


## 集成验证与冲突规则

默认controller使用真实IDB；单元测试只通过显式test fixture注入替身，不构成生产fallback。启动读取与网络对账分开，失败保留草稿；恢复GET查无回执不自动POST，用户明确继续才解密原请求并使用原operation。服务端已确认的受理不会因本地mark失败而否认。首次未知请求的重放若遇到接纳前429，仍保留原operation的不确定性；命令事务内的明确状态冲突另行处理。

发送前冻结当前贡献范围。服务端`link_occurrences`给出每个有效规范化URL在原文中的UTF-16位置（包括重复），只把实际贡献有效链接的外部指纹写入claims；未识别输入保持未claim。编辑仍完整保留的片段会保留来源，实质改变片段则是新手动输入。延迟unknown分类保留冻结上下文，显式选择链接后才记录操作。

若同一组合中的指纹已被其他确认绑定到不同/部分批次，事务拒绝重新分配：不派发，不清空输入，恢复已有记录并提示用户移除已确认部分后继续。仍未改变的其余来源保留绑定。这是并发确认冲突，不以新operation绕过已有确认。

完整10秒可见窗口结束后写入展示标记；隐藏/离页/Sheet遮挡暂停。新进程读取已完整展示的done不会重复入FIFO；若进程在窗口完成前结束，下次可重新提供完整窗口，不能用后台时间耗完它。过期且查无回执的未知记录保持可查询，但不阻塞新输入容量，没有假造取消或服务端失败。
