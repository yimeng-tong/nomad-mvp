# 提示强度审计与三项需求微调

**三项直接调整与18组提示方案均已批准并写入规划合同。** 原始审计在2026-09-14完成，18组由用户于2026-09-15单独认可；采用与后续核验见`prompt-strength-adoption-2026-09-15.md`。 建议让可用行程、当前输入和主要操作
占据主页面，非阻断细节以短状态出现，用户需要时再点开核对。需要当场解决的问题只在
受影响字段或操作处说明，不把所有异常都变成弹窗，也不把未保存、未知结果或硬冲突藏起来。

本次检查当前文字合同及原型覆盖登记，涵盖59张Story（7张历史基线、52张当前目标），
归并125类提示场景。范围含S0–S11、旅中餐饮/清单、账号/反馈及桌面运营；没有重新审阅
所有PNG像素或检查运行中的产品。文件里的“显式”“必须”不等于界面已经使用红色或弹窗。
本报告不能证明所有现有实现提示都已修改。

## 建议采用的提示层级

| 层级 | 主流程怎样显示 | 何时查看细节 |
| --- | --- | --- |
| 非阻断建议 | 一条中性、可读的行内说明；同一原因只保留一个入口，不抢焦点或要求确认。 | 用户点击现有地点、路线、来源、FixSheet或整体核查入口；返回保留页面状态。 |
| 当前动作无法完成 | 当前字段/操作区写明具体问题和可用动作，如“未保存 · 重试”。 | 原因可展开，但“未保存/无法提交/尚未确认”等关键结果不能隐藏。 |
| 执行前必须确认 | 在既有最终预览/确认处一次说明范围、后果及重要差异。 | 详细技术依据可展开；重要影响必须在执行前看得到，不加无意义的重复确认。 |

“稍后核对”不代表之后必须完成一张检查表才能继续。默认不新增页面、强制待办或确认步骤；
也不因用户收起提示就改变服务端判断。弱提示保持可读对比度与读屏名称，不能只剩颜色或灰点。

## 建议弱化的场景

以下18组现已获用户明确批准，已按真实能力边界同步；原始提案文字保留用于追溯，当前具体呈现以front-end-spec和正式GWT为准。引用A/E编号可在完整覆盖表定位。

| 场景与归属 | 现有要求或可改进处 | 建议文案/呈现 | 延后查看的内容与保留边界 |
| --- | --- | --- | --- |
| 1. 导入部分识别/部分成功（1.6、1.9–1.10；A03/A06） | 要求真实说明部分未识别、媒体可用或单项失败；未指定统一视觉强度。 | Dock对应批次一行“已添加N个链接，部分内容未识别”；部分保存显示“部分内容已保存”。 | 未识别片段与原因点开该记录看。真正终止仍写“这条导入未完成”，不影响其他任务。 |
| 2. 重复导入（1.8；A07） | 返回已完成记录或原任务进度，不需另一套失败提示。 | “已在灵感库”／“正在导入”，就近提供查看。 | 保留原记录/任务入口，不重复计算，也不泄露其他账号的记录。 |
| 3. 班次/酒店搜索（2.4–2.5；A13/A15） | 没有结果与接口失败均有手动路径。 | 无匹配：“未找到，可手动填写”；请求失败：“搜索暂不可用 · 重试”。 | 错误原因留当前搜索区域；来源详情点开看。无结果不能冒充请求失败，过期/歧义结果采用前仍需处理。 |
| 4. 路程时间未知（2.10、3.2；A25） | 不得显示假分钟数，需要表达路线未知。 | 相邻路线一行“路程时间暂缺”。 | 详细原因/依据进路线详情；不能改为0分钟。依赖可达性才能执行的动作继续按原门禁处理。 |
| 5. 日负荷与普通天气建议（2.14、3.4；A28/A41） | 日负荷有紧凑摘要与限制；远期天气只能作季节参考。 | “较满”“部分通勤待核对”“天气临近出发再核对”。 | 展开日负荷/天气详情看缺失与来源；不为每项估算重复提醒。真实恶劣天气或不可行问题按实际严重性及时显示。 |
| 6. 手动地点使用地标代理（2.15、3.2；A29） | 持续表明“附近估算”及实际地点可能有偏差。 | 地点旁“附近估算 · 以XX为参考”。 | 详情保留“实际位置建议核对”；落位预览仍显示代理身份，不能把地标当目标地址或继承营业/预约事实。 |
| 7. 只有软冲突（3.4；A38） | 当前把冲突统一放进含最高严重级别的banner。 | 改为一个低强调入口：“有N项建议核对 · 查看”。 | 具体日期、原因和修复在原FixSheet/整体核查中展开；跨日可达。hard/soft分类不变，不能把soft说成全部检查通过。 |
| 8. 无法预估住宿影响（3.3；A36） | “暂时无法预估影响，保存后将检查冲突”。 | 精简为“暂时无法预估，保存后会检查”。 | 详细缺失原因进原影响预览；实质变化仍需确认，不能弱化成“无影响”或让结构非法内容保存。 |
| 9. AI无安全调整方案（3.5；A43） | “暂时没有安全的调整方案”加具体原因。 | “这次暂时无法调整”，紧接一句原因与“当前计划未改动”。 | 重述/手动入口保持；不能为了弱化生成不安全方案，也不能隐藏真实硬冲突。 |
| 10. 细节尚未完善/部分完善（5.1–5.2；E5-02/03/04） | 已优先显示基础行程，核查区包含真实完整度。 | 总览只保留两行摘要；细节行可用“还有N处细节可完善 · 去完善”。 | 未生成/失败与“建议核对”在实际槽位详情分清；不逐卡重复提示，不把部分失败包装成全部成功或强制先完善再阅读。 |
| 11. S9/S11非阻断出行提醒（5.1、5.4；E5-05/13） | 要求soft风险摘要可见，并允许继续。 | 统一为“有N项建议核对 · 查看”，保留必要短摘要，用户仍按原主按钮继续。 | 展开查看原提醒；不新增“我已读完”或逐条确认。导出文件离开App后仍须带有必要提醒/来源，不能只留站内入口。 |
| 12. 已完成图片后行程变化（5.5；E5-22） | 精确文案“！现在的行程单有改动，建议重新生成”。 | 去掉感叹号：“行程已有更新，可重新生成”。 | 与图片生成时间并列，按钮沿用“重新生成”；已完成旧图仍可用。尚未完成的旧预览仍须刷新后再生成。 |
| 13. 长行程分图说明（5.5；E5-17） | 已有张数、城市范围与分段解释。 | 主显示“将下载N张长图”，范围按需展开。 | 操作前张数仍清楚，完整城市边界和顺序保持；不加下载前二次核对。 |
| 14. 定位未使用/过期（6.2；E6-05） | “位置已过期，已按行程位置推荐”／“未使用定位，已按行程位置推荐”。 | 主显示“已按行程位置推荐”，旁边保留真实前/后计划地点。 | 点击依据查看未授权、过期或失败的具体原因；重新定位为次要动作。距离基准不可隐藏或说成“离我最近”。 |
| 15. 候选、最近行程、模块读取失败（6.2、7.1、8.6；E6-07/E7-03/E8-15） | 保留已有合法内容与真实恢复，不能失败当空。 | 对应模块“候选暂未更新”／“暂未更新 · 重试”，不扩大成全页警告。 | 原因、截至时间和来源在模块内；撤权立即清掉无权内容。任务真实失败与读状态失败仍分开。 |
| 16. AI清单重复或生成失败（6.4；E6-12/14） | 重复建议默认不选，生成失败可手动添加。 | 重复项“清单中已有”；生成失败“建议暂未生成，可直接添加”。 | 只在该条/当前输入区说明；真正保存失败仍“暂未保存”，不能改成可忽略建议。 |
| 17. 数据副本范围/下载、反馈回执（7.4、7.6；E7-06/08/15） | 需要说明副本范围、保存未知、已收到不等于已处理。 | 生成前简述范围和“副本含个人数据，请妥善保管”；成功回执以编号/时间为主；其他说明小号呈现一次。 | 详细字段/保留政策可展开，关键导出后果仍在执行前可读。账号副本普通浏览器确已发起时可复用“已开始下载，请确认”；不冒充已保存或反馈已处理。 |
| 18. 运营页解释性说明（8.2–8.6；E8-03/05/07/10/15/16） | 各来源有口径、采样、时效、估算/未知及发布/使用区别。 | 金额/状态旁保留最小标签：“暂估”“待核对”“等待使用”“数据截至…”；长定义点“查看来源”。 | 生产发布影响、真实外发、权限及关键未知不后置。现有Sentry/Langfuse内部UI不在本轮要求重绘；运营只需桌面Web。 |

其中7、12、14最直接改变主流程观感；4、5、6、10、11主要收敛重复解释。第8项保留“无法预估”
这一明确事实，不采用过于模糊的“部分影响待核对”。本报告统一非阻断建议入口的文案，避免
同一概念同时叫“风险”“提醒”“核查任务”；实际日期/出行事项本身仍用具体名称。

## 已经足够轻，建议保持

- Library“待定位”点开才选Top-5；未安排必去/顺路候选留在原候选入口，不先弹整库核对。
- S3已明确留空/未知/未决定，S5附加要求折叠，购物标签可选；不新增漏填提醒。
- 规划与导入显示真实阶段，成功/无冲突状态不长期占屏；撤销沿用唯一“撤销8”控件。
- 餐厅不足只显示“+ 添加更多”；无有效商圈结果不展示“附近吃什么”。
- “我的修改”“有未完成的修改”保持短状态；外部分享由用户取消时不当错误。
- 普通图片下载严格保持用户已指定的“已开始下载，请确认”。
- 反馈截图上传不可用时维持置灰控件和可移除预览，不恢复额外失败行/重试行/专用文字按钮。
- 额度、Provider、内部质量/置信度/新鲜度枚举不转为旅行者提示；不新增普通业务监控面板。

## 必须及时说明，但可以简短

| 情况 | 建议呈现方式 | 不可后置的理由 |
| --- | --- | --- |
| 登录/系统权限、S2/S3未处理的必要输入 | 当前控件附近明确提示，只聚焦首个问题；系统授权仅按实际需要触发。 | 不能把未选择当确认，或在授权前取位置。 |
| 必要返程/交通缺失、冻结预约重叠、越界或结构不合法 | “请补充返程安排”“与已预约安排重叠，请调整时间”；保留原修复入口。 | 这些问题影响是否能发布/采用，不属于可忽略的事实建议。 |
| 已发布计划存在hard问题 | 一个简短可达提示“有N项安排需要调整”，不自动打开整个FixSheet；受影响操作旁说明原因。 | 阅读仍可继续，但完善/导出等门禁不能因收起提示而通过。 |
| 未保存/未提交、版本变化、响应未知 | “未保存 · 重试”“行程已更新，请刷新”“正在确认保存结果”。 | 用户必须知道主要事项是否完成；未知不能当成功或失败，也不能盲重发。 |
| 实质住宿/餐厅/跨城/一日游修改、删除及最终AI应用 | 在既有预览集中展示范围、差异和后果。 | 保留唯一明确应用授权；原预约等外部后果不能执行后才披露。 |
| 账号删除与下载前的数据去留选择 | 原确认页一次说明不可撤销及所有设备停止访问等实际后果。 | 不可逆后果必须在最终受理前知晓，不能统一改成“建议核对”。 |
| 运营生产发布、预算调整、暂停/恢复、付费评测或真实发送 | 原确认区集中显示环境、目标、影响及必要金额类别。 | 简化长解释不能移除权限、费用、真实外发和生产影响确认。 |
