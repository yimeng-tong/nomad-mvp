# Evaluation Data, Rule Policy and Operator Entry

## 用户明确要求

本记录对应 Story 8.2 的三条批注。用户于 2026-09-08 批准整张修订 Story、下述采用方案
及 Human Workspace R2；实际部署/套餐/数据传输仍需另行核验。

1. **线上样本可参与评测。** 脱敏筛查姓名、身份证号等直接关联具体个人的信息；
   仅能通过推测间接关联的信息不纳入这项脱敏规则。目的地、酒店 POI、日期、时间、
   路线、偏好和行程约束不因其组合可能间接识别用户就被删除。
2. **按具体规则判定。** 不采用“任一硬约束失败都一票否决”的统一质量门槛；逐条规则
   决定计分、提醒或人工复核，确需阻断的个别规则须明确对齐，不因旧 hard 标签自动继承。
3. **人工参与评估。** 支持人工评分、评语及实验对比中的标注；评估利用 Langfuse 更多
   成熟能力，提供轻量运营入口，承载后台配置与模型迭代评估。

## 解释与实现边界

- 数据处理准确称为“去直接标识”，不宣称不可再识别的匿名化。姓名、证件、个人手机号/
  邮箱、能直接定位账号的标识等按字段与上下文规则筛查；普通 POI 名/酒店名不是人名，
  公开商家联系方式不是用户联系方式。不得用模糊推断无限扩大清除范围。
- API key、Cookie、token、私有访问签名仍不得出现在评测输入/日志/报告里。这是独立的
  凭据安全控制，不是把间接推测重新包装成脱敏要求。普通公开内容链接不等同私有凭据链接。
- 支持运营在已授权的数据范围内选择线上样本或配置有界抽样，经处理后保存独立评测副本；
  不是把全量生产数据库接到 Langfuse，也不自动开启完整生产 tracing。样本收集的实际
  数据范围/权限、存放位置、保留/删除和外发目标在实施时核验，本次不抽取或上传数据。
- 8.1 生产遥测仍只有安全观测字段。8.2 使用独立评测数据入口/命名空间及访问控制，允许
  去直接标识后的完整必要旅行上下文，二者不得共用一个放宽了的遥测出口。
- 评测规则策略不更改 Planner/Validator 运行时合同或代码测试。数据缺失、未执行、解析
  无效属于“证据不完整/不能比较”，不等于模型质量失败，也不能冒充已完成的高分。

## 已批准采用方案

复用 **Langfuse 作为评测操作界面，promptfoo 作为确定性 CI/完整 Nomad 实验执行器**。
只增加最小版本/结果适配、规则策略和数据入选处理，不复制厂商 UI 或引入另一评测平台。

| Story | 已确认职责分工 | 不在该 Story 偷带的功能 |
| --- | --- | --- |
| 8.2 | 样本、自动/人工评分、逐例 A/B、评语、实验 prompt/model 配置与试跑入口 | 不直接发布生产模型；不重建完整后台或治理中心 |
| 8.3 | 生产任务级 Provider/model/回退配置、验证、发布与回滚 | 不用 Langfuse 实验标签直接驱动线上热切换 |
| 8.4 | 平台预算/并发/用量策略编辑与计量核对 | 不向旅行者暴露额度 |
| 8.5 | 终态异常、Telegram 告警与恢复 | 不用评测低分自动报警或改写业务任务 |
| 8.6 | 薄统一入口，汇总并链接前面已可用的界面 | 不重复实现评分器、编辑器、日志搜索；写操作仍由所属 Story 授权 |

8.2 先从 Langfuse 项目直接进入，8.3/8.4 各自提供可用操作；8.6 最后统一导航。
不要求用户等到 8.6 才能评分/调整实验参数。路由/预算页面的具体成熟实现随对应 Story 调研。
Langfuse Playground/UI experiment 适合单 prompt 调试，不自动等价完整 Planner 的多步骤回归；
后者通过受限 CI 的已审核实验任务启动，结果送回同一评测工作区。
