# Story 8.4 金额来源与桌面 Web 范围澄清

用户明确运营者在 Web 上管理，无需移动端适配；并询问策略改后的金额及上游金额来源。
本补充解释拟实现的数据链，不代表已经接入任何生产账号。用户随后于同日批准该补充及修订后的26条GWT，已追加正式epics；
规划批准不等于已经接入生产费用来源或取得运行验收。

## 1. 谁提供什么

| 数据 | 获取方式 | 可信边界 |
| --- | --- | --- |
| Nomad 平台预算 | 运营者在桌面 Web 输入/发布，服务端保存版本 | 这是内部消费上限，不是供应商余额、资费或预期未来支出 |
| 请求用量 | 适配器捕获实际响应 usage/计量元数据及 request id，按真实请求关联账本 | 供应商可能返回 token、缓存细分、图片/音频单位；字段缺失保留未知，具体连接逐一验证 |
| 单位价格 | 从实际收费方官方价目、购买合同或其受支持价目接口取得，登记计价版本 | 不能默认有统一可读取价格 API；转售平台价格优先于模型原厂价，同名模型不等于同价 |
| 计算成本 | 用已报告用量按相应模型/模态/阶梯价格计算，保留原币与定点精度 | 是可追溯的估算成本；供应商另有套餐、折扣、计费舍入或费用修正时可能不同 |
| 已核对扣费 | 该供应商实际支持的费用回执、账单 API，或授权运营者登记有证据的账单核对结果 | 需要时间范围、账户/项目、币种与 request id（若有）匹配；仅有总账时只能做对应范围核对 |
| 供应商账号余额 | 该供应商实际支持的余额接口或带时间的控制台核对记录 | 独立能力；不能用“调用前余额减调用后余额”认定单请求费用，可能同时发生其他请求/充值/赠金/调整 |

服务端只提取必要计量字段，密钥留在服务端。原始 prompts/输出或含个人数据的账单
不得因此被写入 telemetry；人工核对先保存最小证据引用和范围，不增加通用文件上传/
抓取控制台或完整财务系统。

## 2. 本期可落实的成本链

1. **登记资费**：沿受限 Web 管理链提供最小计价记录的查看/登记/检查/版本发布能力，
   由获授权运营者按实际价目填入收费方、连接/模型、单位、币种、输入/输出/缓存或
   媒体/工具阶梯、来源、生效时间。若有可靠官方价目接口可以导入候选，不能静默
   覆盖生效价。记录版本与核验时间；不新增任意 URL 抓取、任意代码公式或供应商账户管理。
2. **调用前预留**：按实际输入和可执行最大输出/媒体/工具范围，用该版本计算保守
   最大成本，再在 Nomad 账本中占住预算。这是内部预留，供应商并未因此提前扣款。
3. **响应后计算**：捕获该 attempt 的真实 usage，用对应价目算成本；例如纯文本、
   无缓存/工具的简化公式为：输入 token / 1,000,000 × 输入单价 + 输出 token /
   1,000,000 × 输出单价。实际实现须处理互斥计量项，不能把包含在总输入中的缓存
   token 再重复计费。真实 usage 是事实，计算出的金额仍标“按资费估算”。
4. **账单核对**：只有该连接提供可信金额证据时，才升级为“上游已核对”。有 request id
   对应到单笔才可单笔确认；只有项目/账号日汇总时保留范围核对与差额，不能均摊后
   把每笔都标实际金额。账单晚到时仍可先用保守成本治理，不必停等账单才能显示业务结果。
5. **缺数据**：只有 usage 没有账单，保留已报告用量与估算费用；连 usage 都没有则
   保留上界占用或按已审定保守规则暂估。没有有效计价上界时不把该付费调用算成已受
   硬预算保护。没有余额接口则显示未接入，不使用假接口/模拟余额补全。

每个生产连接在启用前需要一张能力登记：usage 是否可得、计价来源/适用模型版本、
最大成本是否可约束、单笔费用是否可查、汇总账单维度/延迟、余额是否可查及所需权限。
这些能力是独立开关，不能因支持聊天接口就把全部标为支持。

## 3. 为什么修改策略后会出现另一金额

原型中运营者把日上限从 20 USD 改成 15 USD。假定同一时点已有费用和占用合计 13 USD：

- 发布前可新预留：20 − 13 = 7 USD。
- 发布后可新预留：15 − 13 = 2 USD。

13 的合成构成为已确认 8.20、暂估 0.80、未外发预留 1.50、在途/未知占用 2.50；
它们互斥归类，同一 attempt 结算时替换占用，不是又加一笔。这里所有数值均来自
原型提示词，尚无生产数据；“2 USD”只是 Nomad 的剩余可分配预算。

生产中预览到确认期间可能有新费用入账，所以服务端不能复用图中的固定 13：预览展示
读取时间，发布按当前权威状态处理，随后读取新策略与最新账本展示剩余预算。多个范围
仍需分别满足准入，展示平台余量不代表每个用户/Provider 都能消费全部平台余量。

修改限额不会请求供应商改售价、改充值额或返还已花费用。若 8.3 另外更换模型，后续
符合生效范围的新任务按其真实模型和适用计价版本估价；不能把新价倒算进历史已确认费用。

## 4. 官方能力例证（非 Nomad 已采用连接）

- **Langfuse** 明确区分直接传入的用量/费用与根据模型价格推导的值；未直接提供 cost 时
  可以用 usage 乘价格计算。它的自定义模型价格可维护，但自动计算不能证明供应商账单
  已核对，也不将它变成 Nomad 原子预算权威。
  [官方用量和成本说明](https://langfuse.com/docs/observability/features/token-and-cost-tracking)
- **DeepSeek** 的 GET /user/balance 官方响应提供币种、总余额、赠送余额和充值余额。
  这证明该提供商有账户余额能力，不证明它返回每次请求的扣款金额，也不能推广到所有
  OpenAI-compatible 服务。该示例未用于选择生产供应商。
  [官方余额接口](https://api-docs.deepseek.com/api/get-user-balance/)
- **AMap** 当前定价涉及按服务类别计次、月配额、流量包和折扣，QPS 另行约束。金额核对
  需实际账号/套餐与对应计费规则，不能直接把一次地图响应里的路线数据当作费用回执。
  [官方定价与配额](https://lbs.amap.com/upgrade)

外部资料核对日期为 2026-09-13。DeepSeek chat/pricing 页面本轮工具读取失败，未据此
声明具体当前单价或聊天 usage 字段；仅用成功读取的余额 schema 作能力例证。
